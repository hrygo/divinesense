# Advanced - HITL 交互设计

> Human-in-the-Loop：让 AI 成为思考伙伴，而非全自动工具

---

## 交互哲学

```
┌─────────────────────────────────────────────────────────────┐
│                    传统模式 (v1.3)                         │
│  输入 → AI 分析 → 输出 Issue                                  │
│  (人类无参与)                                                │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│                    HITL 模式 (v2.0)                          │
│  输入 → AI 初步分析 ↔ 人类判断 → 深度分析 → 洞察产出    │
│  (关键决策点人类参与)                                        │
└─────────────────────────────────────────────────────────────┘
```

**核心原则**：
- AI 是"思考伙伴"，提供分析和选项
- 人类负责判断和决策
- 关键节点必须人类确认

## 四个关键交互点

### 交互点 1：分析方向选择

**触发**：发现多个值得深入的方向

```yaml
AI 提问:
  "发现了 3 个值得深入的方向：
   1. 成本优化模式（会话修剪）
   2. 可扩展性模式（插件系统）
   3. 用户触达模式（多渠道）

   你希望我：
   a) 全部分析（推荐）
   b) 重点分析某个维度
   c) 先给我快速摘要"

人类选择:
  - a/b/c → AI 按选择继续
```

### 交互点 2：模式验证

**触发**：抽象出新的模式或假设

```yaml
AI 提问:
  "我注意到一个模式：
   OpenClaw 的'会话修剪'、'记忆压缩'
   本质上都是同一个底层模式：

   【记忆成本管理】→ 在有限资源下最大化价值

   这个归纳准确吗？
   a) 准确，继续
   b) 部分准确，我的看法是...
   c) 不准确，我认为..."

人类选择:
  - a → 继续此模式
  - b/c → AI 整合人类观点
```

### 交互点 3：战略判断

**触发**：需要判断"做/不做"时

```yaml
AI 提问:
  "关于'插件系统'功能：

   正方：用户定制化需求强
   反方：增加维护复杂度

   我的倾向：不做竞品那样的插件，
   而是优化现有工具接口。

   你怎么看？
   a) 同意
   b) 不同意，我认为应该做
   c) 再给我更多分析"

人类选择:
  - a/b → 更新战略建议
  - c → 提供更多数据
```

### 交互点 4：优先级排序

**触发**：生成多个行动建议时

```yaml
AI 提问:
  "基于分析，我建议的优先级：
   P0: 本地记忆索引优化
   P1: 工具接口标准化

   你同意吗？还是需要调整？
   a) 同意
   b) 调整：把 X 提到 P0
   c) Y 不需要做"

人类选择:
  - a/b/c → 更新最终 Issue
```

## 交互模式控制

### 交互深度

```yaml
minimal:    # 仅关键决策
  - 战略方向确认
  - 做/不做判断

standard:   # 标准交互（默认）
  - 分析方向选择
  - 模式验证
  - 战略判断
  - 优先级确认

deep:       # 深度交互
  - 每个阶段都确认
  - 邀请人类输入观点
  - 共同创造
```

### 智能交互

```yaml
自动确认（无需询问）:
  - 低价值判断（明显不适合的功能）
  - 已确认过的模式
  - 非关键的分析步骤

必须询问:
  - 战略方向变更
  - 做/不做判断
  - 高优先级任务
```

## 快捷指令

| 指令 | 行为 | 示例 |
|:-----|:-----|:-----|
| "深入 X" | 聚焦分析 | "深入插件系统" |
| "换个角度" | 尝试不同框架 | "换个角度分析" |
| "为什么" | 解释推理 | "为什么这样归纳？" |
| "确认" | 使用当前假设 | "确认，继续" |
| "调整：..." | 修正方向 | "调整：我觉得是..." |
| "跳过" | 跳过当前分析 | "跳过这个" |
| "总结" | 当前阶段总结 | "总结一下" |
| "完成" | 生成最终报告 | "完成" |

## 交互质量保证

### 设计原则

```
1. 每次交互都有明确目的
2. 选项简洁明确（≤ 4 个）
3. 人类可随时打断
4. AI 记住选择，不重复问
5. 人类可要求"解释推理"
```

### 质量指标

```
• 平均交互轮次：3-5 次
• 每轮理解时间：< 30 秒
• 人类满意度：70%+ 认可 AI 建议
```
