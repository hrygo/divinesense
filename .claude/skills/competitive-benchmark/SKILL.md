# Competitive Benchmark v2.1

## 执行协议

```
Step 1 → Step 2 → Step 3 → Step 4 → Step 5
状态恢复  数据收集  价值三问  战略判断  洞察产出
                (HITL)   (HITL)
```

## Step 1: 状态恢复

```bash
./.claude/skills/competitive-benchmark/scripts/state.sh summary
```

获取上次分析 SHA，判断是否有新变化。

## Step 2: 数据收集

```bash
# 代码结构
mcp__zread__get_repo_structure "openclaw/openclaw" "/"

# 用户反馈（痛点、需求、讨论）
gh issue list --repo openclaw/openclaw --limit 30

# 官方叙事（版本变化、新功能）
gh release list --repo openclaw/openclaw --limit 5
```

## Step 3: 价值三问分析

对每个发现的竞品功能，按顺序回答：

| 阶段 | 问题 | 输出 |
|:-----|:-----|:-----|
| **Q1 问题本质** | 解决了什么痛点？核心矛盾？ | 这不仅是[X]，而是【Y模式】 |
| **Q2 价值来源** | 为什么有价值？成功要素？ | 主要价值：效率/成本/可能性/... |
| **Q3 创造性转化** | 能否用更好方式实现？ | 利用我们的[优势]实现[价值] |

## Step 4: 战略判断

| 决策 | 判断标准 | 询问人类 |
|:-----|:---------|:---------|
| **做** | 符合差异化 + 用户需求 + 我们优势 | ✅ 必须询问 |
| **不做** | 不符合定位 / 跟随无意义 | ✅ 必须询问 |
| **差异化** | 同样价值，独特方式 | ✅ 必须询问 |

**AskUserQuestion 使用时机**：
- 发现 3+ 个深入方向 → 询问分析重点
- 抽象出新模式 → 询问归纳准确性
- 战略方向不明确 → 询问做/不做/差异化
- 优先级不确定 → 询问 P0/P1/P2

## DivineSense 差异化优势

| 优势 | 竞品限制 | 我们机会 |
|:-----|:---------|:---------|
| **本地化** | API 成本限制 | 实现竞品因成本无法做的功能 |
| **单二进制** | Node.js 部署复杂 | Go 性能 + 零依赖部署 |
| **Geek Mode** | 无开发者集成 | Claude Code CLI 深度集成 |
| **个人场景** | 多用户复杂度 | 简化架构，专注体验 |

|:-----|:-----|
